# Бррр!-Эффект — канон

Версионируемый корпус норм Ивана Дьяченко: методологии мышления Бррр!-Эффект и архитектуры инновационного процесса SHIFT+. Бррр!-Эффект выводит идеи за пределы очевидного; SHIFT+ — маршрут из шести шагов, который ведёт от смутного запроса к вердикту эксперта и мандату пилота.

Репозиторий служит единственным источником истины для людей и LLM, которые проектируют фреймворки, готовят программы и фасилитируют сессии.

## SHIFT+ в одной строке

Scope → Highlight → Ideation → Filtering → Tuning ⇄ Expertise

| Шаг | Переход | Выход |
|---|---|---|
| Scope (Запрос) | Смутный запрос → подтверждённый запрос | Job Story+ |
| Highlight (Фокусировка) | Запрос → изобретательская задача | Задача с типом барьера и инвариантом дизрапта |
| Ideation (Генерация) | Задача → пул идей | Таблица I7 |
| Filtering (Фильтрация) | Пул → идея-лидер | Лидер и до двух запасных идей |
| Tuning (Прожарка) | Лидер → идея, готовая к экспертизе | Пакет экспертизы |
| Expertise (Экспертиза) | Пакет → вердикт | «Утверждено» с мандатом пилота, «Возвращено» или «Отклонено» |

## С чего начать

- Понять систему: `02` → `00` → `13` → `01` → `04`.
- Провести шаг: паспорт шага `05`–`10`, затем `14` и нужный файл в `Frameworks/`, затем `15`.
- Выбрать фреймворк под барьер: `03` и `07`, затем `14`.
- Спроектировать новый фреймворк: шаблон паспорта в `14`, раздел 1.

## Правила канона

1. **Один факт — один владелец.** Каждое положение записано в одном файле; остальные на него ссылаются. Если одна сущность определена в двух местах по-разному, канон повреждён и подлежит исправлению.
2. **Иерархия.** Паспорт шага применяет онтологию `01`, но не переопределяет её. Паспорт фреймворка работает внутри шага, но не меняет его архитектуру. `15` не меняет нормативных правил.
3. **Имена.** Методология пишется только как «Бррр!-Эффект». В тексте шаги называются только Scope, Highlight, Ideation, Filtering, Tuning, Expertise; русское имя — только в заголовке. Роли и источники реальности называются строго по `16`.
4. **Термины.** Строго по `13`: «дизрапт», «дизраптивный», «идеальный конечный результат», Big Innovation Idea.
5. **Статусы утверждений.** Зафиксированное положение, гипотеза и проектное предложение не смешиваются.
6. **Вердикт.** Эксперт или команда с его участием выносит вердикт.

## Работа с репозиторием

- Имена файлов не меняются: на них ссылаются другие файлы и скиллы.
- Паспорт фреймворка пишется по шаблону из `14`, раздел 1.
- Правка одного файла требует проверки ссылок на него (`rg` по номеру файла и названию).
- Каждый коммит описывает, какие нормы изменились, а не только какие файлы.
- Редактор: iA Writer или любой редактор Markdown. Рабочее пространство VS Code — `brrr-canon.code-workspace`.
